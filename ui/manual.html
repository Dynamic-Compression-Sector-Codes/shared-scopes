Overview

DCS Oscilloscope Control is a Python application for monitoring, arming, and saving waveform data from multiple Tektronix oscilloscopes connected over TCP/IP. Built with PyQt5 and PyVISA, the application queries all selected scopes in parallel using threading, keeping the user interface responsive even while acquiring data from many instruments.

Key capabilities:

  • Monitor connection status, trigger state, acquisition mode, and sample depth across multiple scopes simultaneously
  • View live waveforms with interactive controls (pan, zoom, decimation)
  • Arm scopes and send software triggers
  • Save waveform data in parallel from all active scopes
  • Manage scope configurations and presets via JSON
  • Support for advanced shot archiving to structured network directories

Quick Start

Windows

  1. Clone the repository: 
    git clone https://github.com/Dynamic-Compression-Sector-Codes/shared-scopes/
cd shared-scopes
  2. Initialize Conda (first time only): 
    conda init powershell
    Restart your terminal after running this.
  3. Set up your scope configuration: 
    copy scopes.template.json scopes.json
    Open scopes.json in any text editor and enter your scope IP addresses, names, and purposes. See the Configuration Reference section for the full schema.
    Important: Back up your scopes.json — this file is excluded from version control. If lost, you will need to re-enter all scope IPs and settings manually.
  4. Launch the application: Double-click run-scope-control.bat in the repository folder.

Every time you run run-scope-control.bat, it automatically pulls the latest code, checks for environment changes, creates a Desktop shortcut on first run, and starts the application.

Linux & macOS

  1. Clone the repository: 
    git clone https://github.com/Dynamic-Compression-Sector-Codes/shared-scopes/
cd shared-scopes
  2. Install Miniconda if not already installed, then initialize it for your shell (first time only): 
    conda init bash
    Restart your terminal after running this.
  3. Set up your scope configuration: 
    cp scopes.template.json scopes.json
    Edit scopes.json with your scope IPs and names.
    Important: Back up your scopes.json — this file is excluded from version control and will not be restored by git pull.
  4. Make the launcher executable (first time only): 
    chmod +x run-scope-control.sh
  5. Launch the application: 
    bash run-scope-control.sh

Every time you run run-scope-control.sh, it automatically pulls the latest code, checks for environment changes, and starts the application. On first run it also creates a launcher shortcut — a .desktop entry on Linux, or a ScopeControl.app bundle in ~/Applications/ on macOS.

macOS — network shares: Archiving mode paths must point to a locally mounted share. Mount via Finder → Go → Connect to Server, then set engineering_drive in scopes.json to the /Volumes/… mount path rather than a UNC path.

Main Interface

Toolbar Buttons

Button Action
Update Table Queries all selected scopes in parallel. Retrieves trigger state, connection status, acquisition mode, record length, sample depth, and data width. Displays results in the table below.
ARM Scopes Arms all selected scopes to wait for a trigger event. Shows a confirmation dialog because arming erases all data on the scopes.
Save Scope Data Saves waveform data from all active scopes in parallel background threads. The GUI remains responsive while files are being written.

File Menu

Menu Item Action
Set Directory… Choose the base folder where waveform files will be saved (standard save mode only).
Set Filename… Set a custom base filename for saved waveforms. If not set, uses auto-generated names in archiving mode.
Set Scope Configuration File… Browse and load a different JSON config file. The application reloads immediately with the new configuration.
Edit Scope Configuration… Opens the Scope Manager dialog to add, edit, or delete scopes and save changes back to the active JSON file.

Scopes Menu

Menu Item Action
Select Scopes… Opens the scope selector dialog to add or remove scopes from the active table. Use preset buttons for quick selection of common groups.

Commands Menu

Menu Item Action
Send to All → Soft Trigger Sends a software trigger to all armed scopes. Shows a confirmation dialog.
Send to All → Single Shot Sets all selected scopes to Single-Shot acquisition mode.
Send to All → Run/Stop Sets all selected scopes to Run/Stop acquisition mode.

Scope Table Columns

Column Description
Scope Scope name and its purpose (from config). Stretches to fill available width.
Trigger Current trigger state: READY (green), SAVE (red), or ERROR (red). Color-coded in the cell background.
Conn Connection status: Y (connected) or N (disconnected).
Mode Acquisition mode: Single-Shot or Run-Stop.
IP Last octet of the scope's IP address for quick identification.
Range Data range (start-stop point): OK if data spans full record length, ERROR otherwise. Orange background = range issue.
#Pts Record length (number of samples in the waveform).
Bytes Bytes per sample: 1 (8-bit), 2 (12/16-bit), or higher.
X Red X button: Click to remove the scope from the active table without deleting it from the config.

Table Row Colors

  • White: Normal operation
  • Light gray: Query in progress
  • Light orange: Connection error or range issue
  • Light red: Acquisition mode error

Table Columns Resizing

All columns except the Scope column have preset widths. Drag any column header divider to resize. The Scope column automatically stretches to use remaining space, ensuring the table always spans the full window width.

Selecting Scopes

Opening the Scope Selector

Click the Scopes → Select Scopes… menu item to open a dialog that lists all configured scopes.

Scope Selector Dialog

The dialog shows four columns:

  • Scope: Name of the scope
  • Purpose: Description from the config (e.g., "Timing Channel")
  • IP: IP address
  • Button Column: "Add [ScopeName]" button for each scope not yet selected

Scopes that are already in the active table have their Add buttons disabled. Click the button to add a scope to the active table; the button immediately becomes disabled.

Preset Selection

At the top of the Scope Selector dialog is a Load Preset dropdown. Select any preset name (e.g., "Shot Config A") to automatically check all scopes in that preset and disable their Add buttons. Presets are defined in the scopes.json file.

Note: The preset dropdown only appears if presets are defined in your configuration file.

Saving Scope Selection

When you close the Scope Selector dialog, your selected scopes are saved to the application settings and automatically restored on the next launch.

Waveform Viewer

Opening a Waveform

Right-click any row in the scope table and select Show Current Waveform… to open an interactive plot of that scope's waveform data. The plot displays all enabled channels from that scope.

Interactive Controls

  • Pan: Click and drag the plot to pan left/right or up/down
  • Zoom: Scroll to zoom in/out
  • Decimate checkbox: Toggle data decimation to smooth large waveforms for faster rendering
  • Decimation value: Text field specifying the target number of points to display. Enter a value (default 20000) and press Enter to update the plot
  • Data Select Mode button: Toggle to enable point selection mode (see below)
  • Legend: Color-coded list of channels in the upper right; check/uncheck to show/hide channels

Cursor Position

At the bottom of the waveform window, a label displays the current cursor position in the plot: (x-time, y-voltage).

Data Point Selection

Click the Data Select Mode button to enable point selection mode. In this mode:

  • Click on the plot to snap to the nearest data point on any visible curve
  • An X marker appears on the selected point
  • The point's exact coordinates are displayed in a tooltip near the marker
  • Click again to select a different point, or toggle the button off to exit selection mode

Decimation Behavior

When decimation is enabled, the application automatically reduces the number of displayed points to match your target value. This significantly speeds up rendering for very long waveforms (hundreds of thousands of samples) without losing critical data information.

Scope Manager

Opening the Scope Manager

Go to File → Edit Scope Configuration… to open the Scope Manager dialog. This dialog lets you add, edit, and delete scope definitions directly in the application.

Scope Manager Dialog

The dialog displays a table with three columns:

  • Name: Scope identifier (e.g., "Scope1", "Scope11")
  • IP: IP address of the scope
  • Purpose: Human-readable description (e.g., "Timing Channel", "Velocity")

All cells are editable — click a cell to change its value.

Manager Buttons

Button Action
Add Row Inserts a new scope row with placeholder values (ScopeNew, 0.0.0.0, empty purpose). Edit the values as needed.
Delete Selected Removes the currently selected row (click a row to select it). The scope is deleted from the table but must be saved to persist the change.
Open File… Opens the configuration file in your default text editor (enabled only if a config file is currently loaded).
Reload from File Discards all edits and reloads the scope table from the active JSON file on disk. Use this to pick up external edits (enabled only if a config file is loaded).
Save Applies your changes: rewrites the active configuration file with the updated scope list and closes the dialog.
Cancel Closes the dialog without saving any changes.

Workflow

  1. Make edits to the scope table (add, modify, delete rows)
  2. Click Save to write changes to the JSON file and apply them
  3. The main window will rebuild its scope list and table automatically

Alternatively, you can edit the JSON file directly in a text editor and click Reload from File to pick up the changes without restarting the application.

Save Modes

The application supports two save workflows, depending on whether you have archiving enabled in your configuration.

Standard Save Mode

Used when "archiving": { "enabled": false } in your JSON config (or no archiving section is present).

  • Use File → Set Directory… to choose a save folder
  • Click Save Scope Data in the toolbar
  • All waveforms are saved as .isf (Tektronix binary format) files directly to your chosen directory
  • Files are named {filename}_S{scope#}C{channel}.isf
  • If a file with the same name already exists, the app appends a number (_1.isf, _2.isf, etc.) to avoid overwriting

Advanced Shot/Platform Archiving Mode

Used when "archiving": { "enabled": true } in your JSON config. Designed for labs with a structured network archive.

  • The Platform dropdown appears in the main window toolbar
  • Select the active platform (e.g., "Gas Gun", "Laser") from the dropdown
  • The application automatically determines the next shot number based on existing folders in the archive
  • The shot name is auto-generated as {YY}-{PLATFORM}-{SHOT#} (e.g., "26-2-042")
  • Files are first staged to a user data directory, then copied to the central shot archive
  • Shot folders are created automatically in the archive on the first save

Archive paths, platform definitions, and directory structures are configured in the "archiving" and "platforms" sections of the JSON config file.

Configuration Reference

Configuration File Format

All application settings are stored in a JSON file (typically scopes.json). The file structure is as follows:

{
  "app_title": "My Lab Oscilloscope Control",
  "scopes": {
    "Scope1": {
      "ip": "192.168.1.10",
      "purpose": "Timing Channel"
    },
    "Scope2": {
      "ip": "192.168.1.11",
      "purpose": "Velocity"
    }
  },
  "presets": {
    "Shot Config A": ["Scope1", "Scope2"],
    "Shot Config B": ["Scope1"]
  },
  "platforms": [
    {
      "label": "Gas Gun",
      "code": "1",
      "subdir": "GG-1",
      "dir_type": "gun"
    },
    {
      "label": "100J Laser",
      "code": "C",
      "subdir": "ID-C",
      "dir_type": "laser"
    }
  ],
  "archiving": {
    "enabled": false,
    "engineering_drive": "//server/share/",
    "gun_shot_data_path": "Shot Data",
    "laser_shot_data_path": "Laser/Shot Data",
    "user_data_path": "User_Data"
  }
}

Schema Details

Field Type Required Description
app_title string No Custom window title bar text. Defaults to "Oscilloscope Control".
scopes object Yes Dictionary mapping scope names (e.g., "Scope1") to scope objects with ip and optional purpose fields.
scopes[name].ip string Yes IPv4 address of the scope (e.g., "10.54.235.87").
scopes[name].purpose string No Human-readable description of what the scope measures (e.g., "Timing Channel").
presets object No Named groups of scope names for quick selection. Each preset is an array of scope names that exist in the scopes dictionary.
platforms array No (but required if archiving is enabled) List of experimental platforms used for archiving. Each platform has label, code, subdir, and dir_type.
platforms[].label string Yes (if platforms list exists) Display name (e.g., "Gas Gun (D)", "100J Laser (C)").
platforms[].code string Yes (if platforms list exists) Platform identifier code used in shot naming (e.g., "1", "C", "2").
platforms[].subdir string Yes (if platforms list exists) Subdirectory path relative to gun or laser base path (e.g., "ID-D-1").
platforms[].dir_type string Yes (if platforms list exists) "gun" or "laser" — determines whether to use gun or laser archive path.
archiving.enabled boolean No Enable advanced shot archiving workflow. Defaults to false.
archiving.engineering_drive string No (required if archiving is enabled) UNC path to the engineering network share (e.g., "//164.54.235.60/Engineering").
archiving.gun_shot_data_path string No Relative path to gun shot data within the engineering drive. Defaults to "Impact Facilities/Shot Data".
archiving.laser_shot_data_path string No Relative path to laser shot data within the engineering drive. Defaults to "Laser Shock/Shot Data".
archiving.user_data_path string No Relative path to user staging directory. Defaults to "User_Data".

Loading a Different Configuration File

Go to File → Set Scope Configuration File… and browse to any .json file on your local machine or network. The application reloads immediately with the new configuration, and the path is remembered for future launches.

Troubleshooting

Scope shows as disconnected or "VI_ERROR_RSRC_NFOUND"

Cause: The IP address in scopes.json is incorrect, the scope is turned off, or the scope is on a different subnet than expected.

Solution:

  • Verify the scope is powered on and connected to the network
  • Check the IP address on the scope's front panel or LAN configuration menu
  • Confirm that your computer can reach the scope's IP (ping test in command prompt)
  • If the scope has multiple network interfaces, check if it is on a different subnet (e.g., 164.54.235.x vs 10.54.235.x)
  • Update the IP in scopes.json via File → Edit Scope Configuration…

Application doesn't start or crashes after "git pull"

Cause: The environment.yml may have been updated, requiring a Conda environment rebuild.

Solution: The launcher automatically detects and applies environment.yml changes. Simply run the launcher again and allow it to complete the update. If the issue persists, delete the scope_control Conda environment and let the launcher recreate it:

conda env remove --name scope_control
Then run the launcher again.

Conda not found or "conda not recognized"

Cause: Conda is not installed, or PowerShell cannot find it.

Solution:

  1. Ensure Miniconda or Anaconda is installed on your system
  2. Run the following command in PowerShell once, then restart your terminal: 
    conda init powershell
  3. If conda is still not found, check that conda.bat is in your system PATH

Cannot save waveforms: "Cannot create save directory"

Cause: The chosen save directory doesn't exist or you don't have write permissions.

Solution:

  • Verify the directory path exists and is accessible
  • In archiving mode, check that the engineering drive path is correct and mounted
  • Use File → Set Directory… to choose a different directory
  • Ensure you have write permissions to the directory

Waveform data is incomplete or incorrect

Cause: The scope's data range is not set correctly (not spanning the full record length).

Solution:

  • Check the Range column in the scope table — if it shows "ERROR", the data window is not set to capture the full record
  • On the scope, use the DATA START and DATA STOP menu items to set the range to span the entire record length
  • Click Update Table to refresh the display

Save fails on some scopes but succeeds on others

Cause: One or more scopes have disabled channels, timeout issues, or connection problems during the save operation.

Solution:

  • Check the warning dialog at the end of the save operation for a list of failed scopes and channels
  • Verify that the failed scope is connected and armed
  • Enable the desired channels on each scope before saving
  • Try saving again; if the problem persists, try updating the table first to confirm connection

Scope Manager changes not appearing in the main window

Cause: The Scope Manager dialog was not closed with the Save button, or the file was corrupted during save.

Solution:

  • Open File → Edit Scope Configuration… again
  • Click Reload from File to discard unsaved edits and reload from disk
  • Make your changes and click Save (not Cancel)
  • The main window will automatically rebuild its table

Platform dropdown is missing

Cause: Archiving is disabled in your configuration file.

Solution:

  • If you want to use shot archiving, edit scopes.json and set "archiving": { "enabled": true }
  • Ensure the platforms and archiving sections are properly configured
  • Go to File → Set Scope Configuration File… and reload the file, or restart the application

Cannot find engineering drive location

Cause: The UNC path specified in archiving.engineering_drive is incorrect or the network share is not mounted.

Solution:

  • Verify the UNC path is correct (e.g., "//server-name/share-name" or "//ip-address/share-name")
  • Try to access the path directly in File Explorer: press Win+R, type the path, and press Enter
  • If the share is not accessible, contact your network administrator
  • If prompted while changing platforms, click Set Engineering Drive Location to specify a different path
  • The application will remember the new path for future sessions

Waveform viewer window doesn't open

Cause: The scope is not responding to waveform queries, or no channels are enabled on that scope.

Solution:

  • Verify the scope is connected and has channels enabled
  • Click Update Table to refresh the connection status
  • Ensure the scope is armed and has acquired data (not in the middle of another operation)
  • Check the console output for detailed error messages

Linux/macOS: conda.sh not found

Cause: Conda was installed to a non-standard location, or conda init bash has not been run.

Solution:

  • Run conda init bash once after installing Miniconda/Anaconda, then restart your terminal
  • Verify the install location with conda info --base — confirm that etc/profile.d/conda.sh exists under that path
  • The launcher searches common paths including Homebrew locations on macOS; if yours differs, source it manually to confirm it works before filing a bug

Linux: application window does not appear

Cause: PyQt5 may not be able to connect to the display server.

Solution:

  • Ensure you are running in a graphical session (not a headless SSH session)
  • If connecting via SSH with X forwarding, use ssh -X or ssh -Y and ensure X11 is running locally
  • On Wayland, try setting QT_QPA_PLATFORM=xcb before running: QT_QPA_PLATFORM=xcb bash run-scope-control.sh

macOS: "unidentified developer" or app won't open

Cause: Gatekeeper blocks apps not signed with an Apple developer certificate.

Solution: Right-click ScopeControl.app → Open → Open anyway. This is a one-time bypass and only needs to be done once.

macOS: archiving mode paths not found

Cause: UNC paths (//server/share/) are not directly accessible on macOS — network shares must be explicitly mounted first.

Solution:

  • Mount the share via Finder → Go → Connect to Server (⌘K), or mount_smbfs //server/share /Volumes/share from Terminal
  • Set "engineering_drive" in scopes.json to the mounted path, e.g. /Volumes/Engineering/
